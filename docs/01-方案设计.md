## 项目缘起

这个项目源于一段真实的审计经历。

多年前，作者还是一名刚入行的审计新人，在对某大型集团执行货币资金审计时，按银行对账单逐笔核对资金流水，却怎么也对不上。当时以为是自己粗心——因为身边有经验的人看到"对不上"，往往会想办法把底稿调整到企业希望的版本，很少有人多问一句。作者没有调整，而是坚持回到银行对账单的原始凭证去查。这份坚持的代价，是没能通过试用期。多年之后，该集团的负责人因经济问题被查处——当年那个"对不上"，是真的。

这段经历点破了财务舞弊里最要命的一环：**"对不上"很多人能看到，但看到之后敢不敢较真、会不会被人情与压力调成"企业想要的版本"，才决定了舞弊能不能得逞。** 问题从来不只是技术，更是人在压力下的立场。

"图灵哨兵"想做的，正是把这种曾经依赖个人勇气、甚至要付出代价的"较真"，固化成一种系统能力——**一个不吃饭、不怕辞退、不欠人情、不会被约谈，因而不会把"对不上"调成"对得上"的审计 Agent。** 它按银行对账单核资金流，对不上就是对不上；它拿合同去撞报关单，条款套利就无处遁形；它用物理约束反推账面存货，塞不进仓库的货就是虚的。它不替代审计师的最终判断，但它让"发现异常"这件事，不再取决于某个新人当天有没有勇气。

（说明：本节不点名具体单位、不涉及任何未公开信息，仅陈述已进入公开司法程序的事实与作者亲历的方法论。）

## 一、项目定位

**项目名称（暂定）：图灵哨兵 — 图增强的财务舞弊尽调多 Agent 系统**

一句话：面向 A 股上市公司财务舞弊识别场景，站在**独立第三方审计视角**，用一支多职能 Agent 团队，把资深审计师"不信单一账目、用多个独立来源交叉找缝"的实战手感，做成「目标输入 → 多源取数 → 图谱 + GNN 结构异常 → 交叉勾稽验证 → 出具带依据的风险尽调清单」的自主闭环。

**与已有方案的根本区别**：阿里云开源的 DianJin-SKILLS（百技图，133 个金融 Skill）站在**银行/卖方视角**（这笔贷款要不要批），且其"关联方分析"本质是让大模型读文本做总结；本项目站在**独立审计/舞弊识别视角**（这家公司报表有没有造假），并以**图神经网络在真实关系图上计算结构异常**为核心——这是读文本的 LLM Skill 抓不到的信号。两者不冲突：本项目直接复用 DianJin-SKILLS 作通用能力底座，把差异化集中在审计 know-how + GNN 这一层。

核心差异化：**根因定位 Agent 内置图神经网络（GNN）**，在关联方交易、股权穿透、资金往来构成的关系图上做舞弊团伙识别与结构异常检测——已在 FiGraph（A股上市公司真实数据集）上跑通验证（详见技术底牌一节）。

## 二、场景与痛点（对应评审「场景价值」25%）

**定位与目标用户**：本系统站在**独立第三方审计视角**，做**全域外部风控**——不依附于被审视主体的内部数据，只用公开信息（年报、公告、处罚、判决、关系图）从外部独立判断一个主体的真伪与风险。目标用户是需要"独立、外部、可追溯"地识别主体风险的角色：

1. **一级市场投资尽职调查**：投前对标的公司做财务舞弊、资金占用、隐性关联的独立核查（PE/VC/产投、FA、尽调团队）。
2. **二级市场实时风控与风险识别**：对持仓/拟投上市公司做财务造假预警、风险传导监测（资管、券商研究、量化风控）。
3. **审计与合规尽调**：会计师事务所、律所、监管辅助场景下的舞弊线索识别与证据固定。
4. 同一套能力也可迁移到金融机构内部风控（银行/消金反欺诈）。

**真实痛点**：
1. **信号过载、噪声高**：财报、公告、舆情、处罚、关系图多源涌入，同一风险被重复提示，尽调人员疲于奔命。
2. **根因靠人肉查图**：识别舞弊团伙、担保圈、资金空转、隐性关联要人工在关系图里一层层追，慢且易漏。
3. **发现即止步**：传统尽调发现风险后，缺少"违规如何追责、投资者损失如何测算"的下游闭环。
4. **不留痕、难复用**：判断依据散落、事后难追溯，复盘经验换人就丢。

**价值收益**：把独立第三方"用多个独立来源交叉找缝"的审计手感做成系统能力，从"发现风险"延伸到"追责测算"，全程决策轨迹 + 凭证出处标注、可复现可审计（⚠️ 更正：非 Trace/审批留痕基础设施，见 §四末）。**场景可迁移性强**——一级尽调、二级风控、审计合规、机构内部风控换知识库与规则即可迁移。

## 三、多 Agent 架构（对应评审「Agent 能力与任务闭环」25%）

**框架平台中立**（无界应用赛道不强制特定框架，可用 LangChain / Dify / Coze / AutoGen / ModelScope 等任意平台）。**当前落地为纯 Python 依赖注入编排**（`demo/agent_orchestrator.py`，端到端可运行、可自证），编排层与模型层解耦、可插拔。核心是一个 **Planner 自主规划**——不走写死流水线，据当前风险局面自主决定调用哪些能力（见下 §8.2.3）。设计 **5 个职能 Agent**（满足 ≥3 硬要求）：

| # | Agent | 职责（独立第三方审计视角） | 关键能力 |
|---|---|---|---|
| A1 | **信号聚合 Agent** | 多源风险信号接入、去重、降噪、分级 | 7类财务信号引擎、相似告警聚类、优先级打分 |
| A2 | **图谱根因 Agent** ★ | 在关系图上做舞弊团伙识别、担保圈检测、风险传导分析 | **GNN 打分（FiGraph 迁移）** + 图查询 |
| A3 | **处置追责 Agent** | 对已认定/高风险线索测算行政/刑事/民事三线责任与投资者索赔框架 | 法条库检索 + 判罚测算 + 置信度标注 |
| A4 | **合规审计 Agent** | 校验是否越界、生成可追溯审计报告、高风险动作拦截送人工 | 合规规则库 + 审批/回滚 |
| A5 | **复盘沉淀 Agent** | 事件复盘、生成风控知识条目、回写知识库 | 结构化摘要 + 知识库写入 |

**任务闭环 7 环节**（严格对齐手册 §8.2 Agent 应用闭环要求）：
① 任务输入（用户输入标的/尽调问题）→ ② 意图理解（识别目标与风险边界）→ ③ **任务规划**（Planner 拆解目标、判断需调哪些工具/知识库/人工确认）→ ④ 能力调用（财务信号 / 图查询 / GNN / 公告资料理解 / 法条检索，按规划取用）→ ⑤ 结果交付（融合成可理解、可操作、可溯源的研判）→ ⑥ 验证与反馈（决策轨迹 + 可复现脚本；⚠️ 非 Trace/Log 基础设施）→ ⑦ 安全边界（高风险转人工，不定性）。

**安全边界（硬红线，对齐手册 §9.3）**：系统只做**辅助分析与风险提示**，不替代金融机构的投资判断、授信审批、保险赔付、风险决策或法律合规意见。高风险动作一律进人工复核，Agent 不自动执行、不对任何主体作违法/有罪定性。

**任务输入支持自然语言（§8.2.1，已落地 `/api/task`）**：用户不必输代码，可直接提问——"康美药业有没有财务造假风险""600519 和 000651 哪个更干净"。意图理解层（LLM 解析 + 正则兜底）识别公司与问题类型，Planner 据此自主拆解、规划能力调用；识别不出公司则提示补充，域外问题礼貌拒答。

核心可复用能力清单（每个附：名称/用途/输入输出/调用条件/依赖/失败处理/安全边界/复用价值）：

| Skill | 用途 | 输入 → 输出 | 复用价值 |
|---|---|---|---|

**工具调用全透明（§8.5，已落地）**：每次能力调用都显式标注四要素——调用方式（如 AkShare 巨潮公告 HTTP 接口）、权限范围（只读公开数据、不涉隐私、不越权）、返回处理（标题须匹配真实公告防幻觉）、失败降级（网络失败→关键词粗筛，LLM 失败→规则综述，均不阻断）。评委可逐项审计"Agent 调什么、为什么、越不越权、出错怎么办"。

**可操作输出 + 有效性自证（§8.3 + §8.2.6，已落地）**：研判不止给风险档位，还生成**可操作核查清单**（据命中信号给下一步动作：调对账单、比对利息、穿透其他应收款……用户拿了能干活）；并附**有效性自证**——康美三年回测均命中最高档且与证监会认定一致、可 `python run.py` 复现、对茅台不误报（含格力误报已自我校准）。

**MCP（推荐可选）**：外部系统（工单系统、征信接口、图数据库）通过 MCP 接入；未用 MCP 的部分给出等价集成契约（协议/鉴权/Schema/错误处理/审计）。

**可观测（推荐可选）** ⚠️ **更正（2026-08-11 逐条核对代码后）**：本项目**未实现** Trace/Span、结构化 Log、Metrics 埋点。实际有的是"可读决策轨迹（trail，内存 list）+ 确定性引擎完全可复现 + 凭证出处标注"。这套东西对审计场景更实用（可逐条复算），但**它不叫可观测性，不该用那个词**。Trace/Metrics 为复赛期计划项。

**RAG（推荐可选，至少实现 2 项）** ⚠️ **更正**：早前表述"四项全做"与实现不符，实际状态如下——
① Agent 记忆存储 🔴 无实现；② 制度知识库 🟡 **是 JSON 按条文 ID 精确查找，非向量检索**（`law/penalty_calc.py:find_statute`）；③ 共享事件档案状态管理 🔴 无实现（A5 仅设计）；④ 轨迹可观测 🟡 决策轨迹未落盘。
**即：严格意义上一项都未达"RAG"标准。** 手册 §9 要求能力披露真实，宁可少说不可虚报。详见 `初赛第二版-递交/03-Agent架构与能力.md` §七。

## 七、未来蓝图：从"检测器"到"传播式反舞弊网络"（可扩展性）

> 本章是项目的长期愿景，用于说明作品的成长天花板；**不属于参赛 MVP 交付范围**（MVP 范围见第八节，切分清晰）。

### 7.1 愿景：让"较真"从个人变成一张会自己长的网

"图灵哨兵"的终局，不是一个装了 N 条规则的检测器，而是一个**越用越聪明、永不过时的反舞弊生态**。它的思想承接项目缘起：当年"看到对不上、敢较真"的只有一个人，还付出了代价；未来，要让**每一个撞见异常的普通人**——审计、投行、供应商、员工、投资者——都能安全、有回报地把线索说出来，并最终被现实验证。

### 7.2 自迭代：舞弊情报官 Agent

在检测闭环之外增设 **舞弊情报官（Intelligence Agent）**，形成"越吃越强"的正循环：
- **搜集**：持续抓取证监会新处罚决定书、问询函、爆雷公告、财经调查报道；
- **提炼**：从每个新爆案例中自动提炼"本可用什么信号提前发现"，生成新的报警信号；
- **迭代**：新信号写入方法论知识库，供检测 Agent 下次调用；并用新真实案例反向验证与微调 GNN。

于是"方法论补不完"的矛盾被化解：**系统自己补**，作者的四个案例只是启动种子。

### 7.3 众包激励：传播式的线索网络

- 任何人可提交"某公司异常"线索，经验证为真可获**积分/现实奖励**，激励自适应放大参与规模；
- 沉淀出的"舞弊信号知识库"本身**开源**，成为社区可共建的公共资产——直接呼应 GOAI"开放、共享、共建"主张。

### 7.4 防骗五道闸（激励一旦开启，作弊者第一个来）

激励=靶子，会招来乱报刷分、诬告做空、女巫攻击（一人多号自证）、合谋背书。五道闸层层拦截，且**其思想与反舞弊同源——不信单一来源、用独立证据交叉、用图结构抓合谋**：

1. **只收证据不收感觉**：线索必须附可撞独立来源的证据（报关单、银行流水、公告页码），无法被独立源印证的不进池子；
2. **先质押后奖励**：提交需质押积分，证伪/恶意则扣除，作恶有成本；
3. **延迟结算、绑定最终验证**：积分待权威事实（立案/处罚/更正公告/判决）出现才结算，奖励"预警最终被现实证明对的人"，而非"喊得响的人"；
4. **GNN 抓女巫与合谋**：一人多号互相点赞，会在"谁给谁背书"的关系图上形成异常闭环结构——**用抓公司舞弊团伙的同一套 GNN 武器直接识别刷分团伙**（技术复用）；
5. **声誉分层 + 人工终审**：按历史命中率分层权重与质押；高价值线索经专业人士复核方可对外披露，绝不由 Agent 单独给公司"定罪"（合规红线）。

## 九、知识产权与合规披露

审计出身的合规敏感度是本项目的天然优势。本项目在开源大赛语境下，主动把"披露"做到超出要求的程度——这既是防"披露不实致除名"的护栏（大赛红线：数据/License/API/依赖披露不实可扣分或取消资格），也是给评委的成熟度加分项。

### 9.1 开源协议与署名
- 采用 **Apache-2.0**：允许他人复用，但**必须署名、保留来源标注**。即使被复用，原作者身份不可抹除，复用者是"站在肩膀上"。
- 项目与发起人强绑定：缘起、方法论均署作者真实审计经历，形成人格化品牌护城河。

### 9.2 第三方依赖完整披露（配套自动化工具）
本项目配套 **自动化依赖复核工具**（`tools/dep_audit.py` + `deps_registry.json`），以"账实核对"方式运行：
- **登记册（账）**：申报项目使用的全部第三方资产（数据集、模型、框架、Skill、API）；
- **扫描（实）**：自动扫描代码 import 与文档关键词，识别真实使用的第三方资产；
- **核对**：账实比对，自动揪出"使用了但未申报"项，生成 `DEPENDENCIES.md` 披露清单。
- 已覆盖：FiGraph、GraphSAGE、PyTorch/PyG、scikit-learn、NumPy、pandas、DianJin-SKILLS、FastAPI/AkShare 等。

> 这把"漏标来源"从"靠记忆"变成"靠证据 + 定期复核"，是审计"底稿留痕"思想在工程上的落地，也是本项目区别于其他队的合规专业度体现。

### 9.3 数据合规边界
- **FiGraph**：学术公开数据集，**仅限参赛/研究用途，不得商用**；引用原论文；遵守官方使用条款。
- **合成/脱敏数据**：说明模拟逻辑与适用范围。
- **绝不使用**任何未授权、未公开的真实业务数据（个人信息、企业内部数据、银行流水原始件等）。
- **行业边界**：系统输出为带依据、标置信度的风险线索，**不构成审计结论，不替代注册会计师的专业判断与最终意见**；高风险线索强制标记"需人工复核"。
